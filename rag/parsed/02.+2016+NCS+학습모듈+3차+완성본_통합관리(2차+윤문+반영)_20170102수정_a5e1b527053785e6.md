# NCS 학습모듈의 이해

※ 본 학습모듈은 「NCS 국가직무능력표준」 사이트(http://www.ncs.go.kr) 에서 확인 및 다운로드 할 수 있습니다.

# (1) NCS 학습모듈이란?

- 국가직무능력표준(NCS: National Competency Standards)이란 산업현장에서 직무를 수행하기
- 위해 요구되는 지식·기술·소양 등의 내용을 국가가 산업부문별·수준별로 체계화한 것으로
- 산업현장의 직무를 성공적으로 수행하기 위해 필요한 능력(지식, 기술, 태도)을 국가적 차원에서
- 표준화한 것을 의미합니다.


- 국가직무능력표준(이하 NCS)이 현장의 '직무 요구서'라고 한다면, NCS 학습모듈은 NCS의
- 능력단위를 교육훈련에서 학습할 수 있도록 구성한 '교수·학습 자료'입니다. NCS 학습모듈은
- 구체적 직무를 학습할 수 있도록 이론 및 실습과 관련된 내용을 상세하게 제시하고 있습니다.

# 필요 지식 /

#  프로젝트 타당성 조사 보고서의 이해

프로젝트 타당성 조사 보고서는 해당 프로젝트의 시작 이유를 근거로 만든 내용이다. 프
로젝트 시작의 예는 고객의 요청, 정부 법규의 변경, 기술의 진보, 새로운 시장의 진출 등
의 이유가 될 수 있다. 조사 보고서에는 일반적으로 다음의 요소가 포함될 수 있다.

# 1. 프로젝트의 범위

프로젝트의 규모를 파악하는 것은 전체 프로젝트의 일정, 원가, 품질 및 리스크관리의 기
본적인 정보가 되기 때문에 전체 규모를 파악하여야 한다. 프로젝트의 범위 배경을 이해
하는 것은 전체 프로젝트의 개요를 파악할 수 있는 중요한 요소이기 때문에 이해관계자들
의 초기 요구사항을 검토하여 범위를 파악하여야 한다.

# 2. 프로젝트의 기술적인 측면

이전에 수행되었던 회사의 유사 프로젝트의 내용을 검토한다. 이러한 유사 프로젝트에는
기술적인 성공 요소와 실패 요소가 나열되어 있기 때문에 시작하는 프로젝트의 기술적인
측면에 좋은 데이터가 될 수 있다.

3

# 3. 프로젝트의 경제성 분석

이전에 수행되었던 회사의 유사 프로젝트의 내용을 검토한다. 이러한 유사 프로젝트에는
경제적인 측면의 요인들이 나열되어 있기 때문에 시작하는 프로젝트의 경제성 분석에 참
고 데이터가 될 수 있다.

# 4. 프로젝트의 리스크관리 수준

프로젝트에서 요구되는 리스크관리의 수준은 프로젝트의 범위, 일정, 원가, 품질 등과 연
계되기 때문에 전반적인 리스크관리 수준을 파악하고 이해하여야 한다.

#  프로젝트의 선정 배경 및 기법

# 1. 프로젝트의 선정 배경의 이해

프로젝트의 선정은 조직의 기본적인 전략과 비전을 고려하여 선택되어야 된다. 하나의 프
로젝트는 회사의 부분 업무로 수행되기 때문에 조직의 전략을 고려하여 프로젝트의 선정
방법이 선택되어야 한다. 예를 들면 조직의 불량률은 ‘1% 이하’라는 회사의 방침이 준
수되도록 프로젝트가 선정되어야 한다.

# 2. 프로젝트 선정 기법의 이해

프로젝트의 경제성, 기술력, 공급 능력, 관리 능력, 수익성 등 다양한 분석 기법을 적용하
는 방법을 이해한다. 이러한 다양한 분석 기법의 결과로서 일반적으로 다음과 같은 방법
에 따라 프로젝트가 선정된다.

# (1) 편익 측정 기법

프로젝트의 예상 비용과 프로젝트 결과물의 수익을 상호 비교하여 정량화 기준을 설
정함으로써 가장 효율적인 프로젝트를 선택하는 방법이다.

# (가) 투자 수익률법

프로젝트의 투자 금액 대비 이익률을 평가한다. 투자 수익률이 높을수록 프로젝트
의 이익이 많이 발생한다.

4

# (나) 투자비 회수 기간법

프로젝트의 투자 대비 원금을 회수하는 기간을 평가한다. 즉 프로젝트의 투자 원금
을 회수하는 기간이 짧을수록 프로젝트의 투자 가치가 높다.

# (다) 순 현재 가치법

프로젝트를 통해 예상되는 이익을 동일한 시점에서 이자를 할인하여 이익과 지출
을 비교한다. 즉 순 현재 가치가 양수(+)로 나타나는 경우에는 투자 가치가 있다는
의미이다.

# (라) 평점 모델링 방법

프로젝트의 평가에 필요한 요소들을 나열한 후 각 항목별로 가중치를 부여하여 전
체 프로젝트의 가치를 정량적으로 표현하는 방법이다. <표 1-1>은 평점 모델링 방

프로젝트의 근본적인 시작 배경을 파악하는 것은 전체 프로젝트의 이해와 프로젝트의 중

# 1. 내부 프로젝트의 시작 배경

시장의 수요(market demand)로 인하여 프로젝트가 시작되는 배경을 파악한다. 생산성 향

한다.

# 2. 외부 프로젝트의 시작 배경

외부 프로젝트는 고객의 요청, 기술의 진보, 법적 요건, 생태계의 영향, 사회적 요구, 정부
의 간섭과 규제 등이 시작 배경이 될 수 있기 때문에 이러한 요인들을 이해한다. 프로젝
트의 기본적인 요구사항의 내용을 파악함으로써 시작 배경을 이해할 수 있다.

#  프로젝트관리계획의 실행 개요

프로젝트의 실행은 프로젝트 팀이 프로젝트 목표를 달성하기 위해 프로젝트관리계획서에
정의된 작업을 수행하기 위해 다양한 팀에 활동을 지시하고 관리하는 제반 행위를 포함하
는 프로세스이다. 즉 모든 자원을 통합관리하기 위해, 프로젝트 목표를 성취하기 위해, 프
로젝트관리계획서의 기준을 수행하기 위해, 변경에 대응하고 리스크를 완화하기 위해 프
로젝트 계획을 실행하는 과정이며, 프로젝트 팀은 기술적인 영역과 조직 차원의 영역을
관리하게 된다. 프로젝트 인도물은 실행 프로세스를 통해서 만들어지기 때문에 계획을 실
행하는 가장 핵심적인 과정이다(한국프로젝트경영협회, 2013). [그림 3-1]은 프로젝트관리
계획의 실행 사례이다.

#  획득가치관리(earned value management)의 개념

프로젝트의 범위, 원가, 일정을 통합하고 프로젝트의 성과를 측정하는 방법이다. 일정 기
간 동안 계획된 작업량을 실질적으로 얻은 가치 및 실질적으로 소비한 원가와 비교하여,
원가 및 일정의 진도가 계획대로 진행되고 있는지를 결정한다. 다음의 개념을 이해하여야
한다(Project Management Institute, 2013).

# 1. 계획가치(PV: planned value)

예정된 프로젝트의 작업을 완료하기 위하여 승인된 예산으로, 특정 활동이나 작업분류체
계 구성 요소에 대한 작업의 예산이다.

# 2. 획득가치(EV: earned value)

수행된 프로젝트의 작업에 대하여 금액 기준으로 가치를 부여한 금액이다. 작업에 대한
금전적인 기준을 부여하는 것이 핵심 내용이다.

# 3. 실제원가(AC: actual cost)

주어진 기간 동안에 작업을 완료하기 위해 실제로 발생한 총원가이다. 이러한 작업을 위
하여 투입되었던 인적 자원, 물적 자원, 출장비 등이 실제원가가 될 수 있다.

# 4. 성과 차이 관리

해당 기간 동안의 계획된 작업과 실적을 비교한 후, 또 실제로 발생했던 총원가를 비교하
여 프로젝트의 전체 예상 원가를 예측할 수 있는 방법으로 다음과 같은 차이를 식별할 수
있다.

# (1) 일정차이(SV: schedule variance)

계획된 예정일과 실제 완료일 사이의 차이를 의미하며, SV = EV - PV로 나타낸다.
이때 결괏값이 양수(+)이면 계획보다 진도가 빠르다는 의미이며, 음수(-)이면 계획보다
진도가 늦다는 의미이다. 동일한 변수를 가지고 지수로 표현하면, 일정 성과도 지수
(SPI: schedule performance index = EV / PV)로 표현되며, 1 이상은 계획보다 진도가
빠르다는 의미이다.

# (2) 원가차이(CV: cost variance)

활동의 획득가치와 실제원가의 차이로 획득가치(EV) - 실제원가(AC) = 원가차이(CV)로
나타내며, 획득가치에서는 CV = EV - AC로 결괏값이 양수(+)이면 계획보다 예산이 절
감된다는 의미이다. 동일한 변수를 가지고 지수로 표현하면, 원가 성과도 지수(CPI:
cost performance index = EV / AC)로 표현되며, 1 이상은 예산이 절감되고 있다는 의
미이다.

(3) 완료 시점 산정치(EAC: estimate at completion) 예측
프로젝트의 원가를 이미 확정하였지만, 프로젝트를 진행하면서 프로젝트 전체 활동을
완료하는 데 소요되는 원가의 재산정치로서 다음의 세 가지 방법으로 분류된다.

| 조직의 문화 | ‘품질이 최우선임, 개선해 야 함’ | -‘개선점을 실제 적용하는 점에 시간과 자원이 부족 함: 너무 피곤하다’ | - 개선 활동에 대한 동기 부여 및 보상 확대 |


84

#  프로젝트 교훈 정보를 전달한다.

프로젝트관리자는 이해관계자들이 향후에 참고로 활용하기 위하여 기록했던 프로젝트의
교훈 정보를 조직 내에서 참고하도록 전달한다.

#  프로젝트 교훈 정보를 보관한다.

프로젝트의 교훈 정보를 회사가 지정한 장소에 보관하여 정확한 정보가 유지되도록 한다.

수행 tip

- • 프로젝트 교훈 정보의 작성은 프로젝트의 모든 이해
- 관계자들이 참여하여 중요 정보를 기록하여야 한다.
- • 교훈 정보는 명백하고 간결하게 작성해야 한다.

# 학습 7 교수·학습 방법

# 교수 방법

- • 교수자는 프로젝트의 교훈 사례를 보여 주면서 지도한다.


- • 교수자는 학습자들이 실제로 프로젝트의 교훈 작성을 이해하고 충분한 실습을 통해 중요 기법들
- 을 이해하도록 지도한다.


# 학습 방법

- • 프로젝트의 교훈 정보 수집에 필요한 모든 데이터를 확보하여 공유하한다.


- • 실습 팀을 편성하여 프로젝트의 성공 요인과 실패 요인을 취합하여 팀별로 발표를 실시한다.


- • 학습자는 노트북 컴퓨터를 지참하여 실습에 직접 참여한다.

# 피드백

# 1. 문제 해결 시나리오

-‘경험 사례 수집하기’ 학습 내용에 준하여 각 평가 항목 관련 문제 해결 시나리오 시
험을 실시하고, 평가 결과가 일정 점수 이하인 학습자들은 추가로 문제 해결 시나리오
에 대한 학습 후 재시험을 치르거나 학습 결과를 제출하도록 한다.

# 2. 사례 연구

-‘경험 사례 수집하기’ 학습 내용의 절차 등에 대해 각 평가 항목 관련 사례 연구 시
험을 실시하고, 그 결과가 미흡한 학습자들은 추가로 사례 연구를 실시한 후 재시험을
치르거나 부족한 부분에 대해 추가로 설명해 준다.
